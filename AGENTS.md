McDiff is a personal macOS code-review app for agent-generated changes. Build with Swift Package Manager. Package the executable as a native app using `scripts/build-app.sh`. Run `swift test` for domain and Git integration tests.

## Product contract

- Use native AppKit controls and a virtualized continuous diff. Support split and unified layouts, defaulting to split and remembering the choice globally. The toolbar toggle names and depicts the destination layout. Unified source shows deletions before additions, context once, and both old/new line numbers. Comments target their original side and line range in either layout. Switching layouts aligns to the header of the file in view, including after asynchronous measurement. Render only visible rows. Never create one view per changed line across the entire review.
- Support worktree changes since merge-base (committed, staged, unstaged, non-ignored untracked), explicit Git revision comparisons, and GitHub PR URLs.
- GitHub maps repositories to user-selected local checkouts. Never clone automatically, switch branches, mutate working files, or stage content. Fetch missing PR objects without changing local branches.
- Compare pull requests against their actual target branch. When Git reports multiple best common ancestors, use its standard selected ancestor and show a persistent warning that inherited changes may appear. Explain that merging the current target branch into the PR branch outside McDiff can resolve the ambiguous ancestry. Do not silently substitute a direct-tip comparison or a synthetic conflicted ancestor.
- Keep production additions/modifications first, alphabetically, and lower-priority files last in a flat sidebar.
- Disambiguate identical sidebar filenames by walking backward through their directories to the first differing name. Show that directory before `…/filename` when intermediate directories are omitted, including more directories if needed for uniqueness. Use ordinary middle truncation for width overflow. The tooltip shows the complete disambiguated label before width truncation. Searching must not change these labels.
- Remember five global inclusion switches: tests, documentation/non-code, generated/noise, whitespace/imports, and meta changes. Checked means included for review. Unchecked means collapse and auto-review matching files. Existing saved category choices keep their behavior when checkbox polarity changes. Category classification is an explicit skip list: unknown extensions and arbitrary text files have production priority. Classify `.proto` as code. Binary changes collapse and auto-review automatically. Every skipped file supports expansion.
- “Meta changes” defaults unchecked and controls deleted files, removal-only changes with no additions, and content-unchanged moves, copies, mode changes, and other metadata changes. Moves or copies with content edits are reviewable unless another exclusion applies. The other category switches apply independently.
- Markdown is documentation regardless of directory, including test fixtures and generated folders. Changing a skip switch only changes expansion for files whose effective skip status changes. Manual expansion of other files is unaffected.
- Fold imports in Kotlin, Java, Go, TypeScript, Rust, and Python with explicit expansion. Use comparison-side source context to recognize import blocks even when a hunk starts or ends inside one. Never infer imports from a quoted fragment alone. Whitespace between imports belongs to the same fold. Leading/trailing whitespace, code, comments, and hunk boundaries do not.
- The fourth sidebar checkbox, “Whitespace and imports,” defaults on and is remembered globally. Existing saved choices keep their behavior when the checkbox polarity changes. When unchecked, collapse and auto-review files whose only changes are whitespace outside string literals or contents of Imports folds, including package declarations and quoted import paths. Python indentation is ignored while unchecked. Outside Imports folds, changes to string contents or other code do not qualify under this switch. File metadata changes do not qualify either. Display all source lines on expansion. While unchecked, inside mixed-change files, show whitespace-only changes without change signs, red/green backgrounds, or word-change emphasis. Split displays both original texts neutrally. Unified displays paired replacements once, using the new text and both original line numbers. Comments keep their original side and line targets. Checking the switch restores full change emphasis and removes only its automatic review decision, without changing saved manual review marks or comments.
- Classify whitespace and imports against complete comparison-side source. Leave uncertain literal syntax reviewable rather than stripping quoted text or inferring imports from isolated changed lines.
- Syntax highlighting and word-level change emphasis are required. Markdown renders inline by default with a per-file header toggle to source mode for line comments. Split shows both rendered versions. Unified shows only the new rendered version, with source mode available to review deletions. The source/rendered choice lasts for the current review. Do not add a global Markdown preference or separate preview window.
- A fixed review-and-next action must support repeated clicks without moving. Sidebar navigation smoothly scrolls the continuous diff, keeping the selected file highlighted during motion. New selections retarget the scroll. Direct scrolling or code interaction interrupts it. Layout switching aligns immediately to the selected file header.
- File headers have a right-aligned reviewed checkbox alongside the Markdown presentation control. Header and sidebar checkboxes share persisted review state: checking collapses the file, unchecking expands it, without moving the visible header. Auto-reviewed files have disabled checked controls and support expansion through the header disclosure. Failed saves leave review state and expansion unchanged.
- Keep the current file header pinned below the toolbar. The next file header pushes it out. Pinned and inline controls have identical behavior. Use native material that follows window activity, subtly rounded corners, and a gradient on the header material’s own bottom edge. Keep title and controls opaque. Do not fade the scrolling code beneath the header. Import headers scroll normally. Apply a fade at the bottom of the viewport.
- Reveal omitted unchanged sections individually through “Show unchanged lines” and “Show rest of file” rows, without exact counts or a whole-file action. Read source only on click, show loading and actionable retry failures, and keep each section’s control available to collapse it again. Asynchronous wrapping must not move that control. Expansion lasts for the current review only. Revealed lines use original side/line identities and support highlighting, search, copying, and comments without changing review progress. Validate context against the loaded comparison and Git’s canonical content before displaying it.
- Persist local comments with path, side, line range and diff identity. Export/copy Markdown with a short comparison header and path/range/plain comment text. Do not submit GitHub reviews.
- Persist review progress across launches for unchanged diffs. Changed diffs become unreviewed. Diff changes must not delete comments. Clearly flag their stale location.
- Follow system appearance/accent and use Monaspace Neon for source with system monospace fallback. Test the dark appearance.
- Use the Atom One syntax palette and honor the user's preferred coloring.
- Keep line-number gutters compact, without reserved leading icon space and with a 13-point gap between unified number columns. Place change signs after line numbers and before source text. Unified rows share one aligned change-sign column after both number columns. Saved-comment icons and left-facing range connectors occupy the far-right rail only for files/sides with comments. These controls target the original side, including both sides of unified context. Comment markers never replace the change sign.
- Use one native Liquid Glass toolbar integrated with traffic lights, a compact flat native sidebar, and a consistently tinted glass window. Use system-generated toolbar items in the regular unified style, without custom button views or forced control heights. Group related controls with spacing. File-header hairlines and subtle rounded import highlights provide separation. Empty diff cells are transparent.
- Fresh launches show Home with open pull requests authored by the signed-in user across personal and organization repositories, including drafts, newest creation first. Show title, repository, number, creation age, and draft status with native search. Single-click a row to review. A small chain button shown on hover opens GitHub independently. Local comparisons require no sign-in.
- Home hides the review sidebar and review controls. Home and Resume switch screens without reloading the review or changing its position. App activation must not switch screens. Protect unsaved comments when leaving a review.
- Use direct GitHub REST with OAuth device authorization and macOS Keychain credentials, including refresh-token rotation. Do not depend on the gh executable, embed client secrets, or store tokens in preferences. Sign-out clears account-owned Home results.
- The account toolbar button shows a circular GitHub avatar and opens sign-in directly, including when already authenticated. Cancelled or failed sign-in must not change saved credentials or PR results. Replace credentials only after successful authorization and identity lookup.
- Home searches GitHub across matching authored open PRs, not just loaded rows. Use a continuous virtualized list with bidirectional preload and direct page loading, without page controls or loaded-result counters. Query changes reset the list. Keep only the visible working set and nearby rows in memory. Use Core Data batched SQLite scratch storage for fetched pages. Loading must not shift the scroll position. Keep the top inset compact.
- Public releases use ad-hoc signing without a Developer ID identity or notarization. Do not use company signing credentials.
- A single GitHub PR URL dropped on the window or pasted at window level opens through the same comparison flow as Home. Paste within text editors inserts text. Do not monitor the clipboard or add browser extensions.
- Package and modules are McDiff/McDiffCore. The bundle identity is dev.nek12.mcdiff. Use McDiff storage without reading or migrating Slopdiff data.
- Keep review chrome minimal: no raw hunk headers, Original/Changed labels, repeated file categories, reviewed counter, load statistics, bottom hint bar, or comparison-title bubble. The copy action is named `Copy review`.
- Place compact addition/deletion counts beside the filename. Keep Open and Recents on Home. In reviews, align the toolbar separator with the sidebar. Place Home/Refresh on the left. On the right, place Next/Previous/Review-next and a text-free spinner, then flexible space and Search, Wrap, Unified/Split, Comments/Copy/Export.
- Provide text tooltips on buttons and subtle animations for checkbox and state changes. Successful Copy review gives visible, temporary confirmation. Repeated clicks restart it. Animate presentation without moving the fixed review action or introducing animated row-height measurement.
- Dragging on source text selects characters for copying without opening a comment editor. Dragging in the existing line-number gutter selects original lines and opens the non-modal comment editor on release. Empty diff cells and trailing space do not open it. Saved comments have clickable gutter markers. Selecting their range in the gutter reopens them. Save is explicit. Failed saves must not discard unsaved edits. Discard requires an explicit action. Do not add persistent drafts or automatic outside-click saving.
- With the diff or sidebar focused, Space or Enter toggles the current file's reviewed checkbox without advancing. Auto-reviewed files have disabled review controls. Control+Enter opens Finish review. Shortcuts must not intercept typing in search or comment editors.
- Keep the split diff halves exactly equal. Unified source uses the full width. Horizontal overflow and offsets belong to each file and side independently, controlled by trackpad or Shift-wheel over that side. Do not show horizontal scrollbar controls or reserve a layout strip. Every app-owned scroll view respects the macOS Show scroll bars preference, including on-demand overlays and Always. Hide scrollers when content fits. A remembered Soft wrap toggle keeps paired rows aligned and uses original line numbers.
- Expanding/collapsing files or imports and switching Markdown presentation must not move the clicked header on screen, including during asynchronous row measurement.
- Native toolbar search matches paths and displayed old/new text, filters the sidebar by either, highlights matches, and navigates them without changing review state.
- Working-tree reviews always include staged, unstaged, and non-ignored untracked changes. Do not offer a checkbox to exclude them. An explicit branch target is a different comparison source.
- Quit when the main window closes, including when preview windows are open.

## Engineering

- Navigate to a destination immediately, with a presentation transition, before loading its content. Pass lightweight intent such as a PR URL or comparison request through navigation. The destination owns its loading, content, empty, and actionable failure states. Leaving or replacing a destination prevents its pending work from updating the new screen.
- Distinguish simple dialogs from self-contained destination flows. Confirmation, information, and choice dialogs render state and emit actions to their owning screen. Their owner performs business operations and presents further dialogs. Finish review is a simple dialog.
- A self-contained flow can be presented as a sheet and own its business logic, loading, and errors. GitHub Sign-in is such a destination. Its parent receives completion or cancellation rather than managing OAuth steps.

- Automated tests must not present visible windows, sheets, popovers, or steal focus. Keep rendering/layout tests offscreen. Verify visible interaction manually.
- Tests inject isolated credential stores and network transports. They never access the user's Keychain or request system permissions. Production dependencies are supplied explicitly at app startup.

- Keep Git/process work, parsing, and syntax preparation off the main thread. Bound caches and render work. Expose loading and actionable failures.
- Use one domain model and one persistence authority. Write persistence atomically.
- Validate Git refs and paths at the process boundary. Run processes with argument arrays, not interpolated shell scripts. Include stderr in failures.
- Test behavior using real temporary Git repositories, including unusual paths, whitespace-sensitive source, missing refs, ignored/untracked files, binary files, rename/deletion and persistence.
- Verify a release build, actual app screenshots, and a 400-file/30,000-line stress review. Local loading may take up to about two seconds. Network PR loading may take about seven seconds. Scrolling must be fast after loading. Do not present CPU screenshot rasterization or layout timings as frame-rate measurements.
- Keep this file as the contributor contract. The README describes practical user benefits. GitHub Releases and the personal Homebrew tap are published through the release workflow.
